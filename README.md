# SlabReinforcement

Готовые сборки для **Revit 2019–2027**: [SlabReinforcement/bin](SlabReinforcement/bin). Используйте папку своего года `R2019`…`R2027` целиком, вместе с зависимостями. Корневые DLL оставлены для совместимости с прежним загрузчиком **Revit 2023**.

Модуль RibbonCITRUS для построения арматуры плиты в Revit: четыре фоновых слоя, П-образное обрамление краёв и отверстий, дополнительные зоны по цветной расчётной подложке. Направление X задаётся выбранным прямым ребром плиты; Y перпендикулярно ему в плоскости плиты. Раскладка учитывает размещение и поворот плиты и подложки.

Это геометрический MVP с отдельными проверками введённой площади арматуры. Расчёт усилий, трещиностойкости, рабочей высоты сечения и узлов анкеровки/стыков в него не входит. Точные границы приведены в [инженерной записке](docs/validation/2026-10-24-mvp-engineering-scope.md).

**Текущий вариант MVP: только П-образное обрамление.** Результаты проверок, демонстрационная модель и пакет относятся к конкретной сборке: [итоговый протокол](docs/validation/2026-10-24-mvp-results.md).

## Быстрый запуск в Revit

1. Запустите команду, выберите плиту и её прямое ребро для оси X.
2. Выберите работу с расчётной подложкой или **«Фон и обрамление без подложки»**. Для зон укажите импортированный/связанный DWG/DXF. Если Revit не передал слои и цвета, команда запросит исходный DXF и его единицы: метры, миллиметры или сантиметры.
3. На вкладке **«Фон и обрамление»** включите необходимые слои верх/низ X/Y, задайте типы и шаги. Для общего П-обрамления выберите внешний край и/или отверстия и тип арматуры. Длина полки подбирается автоматически по бетону и общему параметру класса арматуры выбранного типа. При полном нижнем фоне позиции следуют его рядам, поле шага показывает X/Y и недоступно для редактирования. Без нижнего фона задайте максимальный шаг П вручную; при одном направлении этим шагом дополняются остальные стороны. Ручное значение сохраняется при переключении режимов.
4. Выбор подложки включает работу с зонами. На вкладке **«Зоны»** выберите слой и плоскость карты, грань и направление; ориентируйтесь на оси предпросмотра. Выберите смысл карты, отметьте цвета и назначьте арматуру. Параметры объединения, округления и автоматических П-окончаний находятся здесь же. В численных режимах введите потребность в мм²/м: верхнюю границу диапазона, а для открытого верхнего диапазона — численный максимум. Значения в см²/м умножаются на 100.
5. Проверьте предпросмотр и диагностику выбранной вкладки. **«Создать армирование» создаёт только выбранную вкладку:** «Фон и обрамление» — отмеченные слои фона и общее П; «Зоны» — зоны и необходимые им П-окончания. Переключение вкладки отменяет прежний расчёт и подготавливает новую операцию. Зоны учитывают подтверждённый существующий фон, но не создают включённый на другой вкладке фон и не вычитают его площадь до фактического создания. Ошибка проверки отменяет выбранную операцию целиком.

Таблица цветов занимает основную часть вкладки; общие настройки расположены внизу. Без подложки вкладка зон недоступна. Настройки сохраняются атомарно в `%LOCALAPPDATA%/CITRUS/SlabReinforcement/settings.xml`; старый XML рядом с DLL переносится автоматически.

## Что строит и проверяет модуль

| Компонент | Поведение |
|---|---|
| Фон | До четырёх слоёв прямых стержней. X расположен снаружи Y с обеих сторон плиты; высоты учитывают физические диаметры. Отверстия разрывают ряды. Концы ограничиваются боковым защитным слоем. |
| Обрамление | П-элементы по выбранному внешнему краю и/или отверстиям, с фактическими дугами загиба выбранного типа Revit. При наличии нижнего фона позиции берутся из точных концов его рядов; при одном направлении стороны без таких концов дополняются вручную заданным максимальным шагом. Без нижнего фона весь выбранный контур использует ручной шаг. Проверяется возможность размещения в плите. |
| Зоны | Один выбранный слой за запуск. NTS объединяет цветные области, учитывает отверстия и продления, унифицирует торцы относительно первого исходного ряда группы. Каждая итоговая группа из двух и более стержней создаётся штатным `PathReinforcement`; одиночные ряды исключаются с диагностикой. Допуск объединения задаётся в интерфейсе, по умолчанию 600 мм. |
| Совместная геометрия | Проверяются новые стержни и существующая арматура выбранной плиты, включая физические позиции `RebarInSystem` из Path/Area. Неподдержанная геометрия блокирует создание. |
| Запись в Revit | Создаётся принятый план. После commit оси, дуги, позиции и число стержней сверяются с ним; фактическая геометрия повторно проходит проверку пересечений и защитных слоёв до принятия общей транзакции. |

Зоны используют отметку соответствующего фона; при его отсутствии — ту же схему X/Y с учётом физических диаметров. Дополнительное пользовательское смещение исключено, старое значение из настроек игнорируется. Предпросмотр показывает все фактические ряды плана и существующего подтверждённого фона без разрежения; подсказка навигации расположена под чертежом.

В ручной раскладке при нехватке прямой анкеровки автоматически создаются **локальные П-окончания только у нужных концов итоговых зон**. Их тип, диаметр, класс и ряды берутся от соответствующей зоны, в том числе при нескольких типах на одной карте. Включать фон или общее П-обрамление для этого не требуется. Точные совпадения с существующими П используются повторно. Соседние свободные и закреплённые ряды объединяются с сохранением их анкеровки; промежуточные добавочные ряды не разрывают регулярную группу. Одиночные фрагменты, не удовлетворяющие правилам группировки и допуску, по-прежнему исключаются с диагностикой.

Для зон и общего П выбраны 100% растянутых стыков в одном сечении. Нахлёст определяется отдельно для каждого типа по общему параметру класса арматуры и выбранному бетону; к полной проекции полки добавляется место под фактический загиб. Автоматический подбор ограничен тяжёлым бетоном B15–B30 и периодической А400/А500. [Формулы, исходные предпосылки и первичные источники](docs/research/2026-10-25-automatic-u-lap-calculation.md).

Для чертежей заполняется штатный **«Раздел»**: фон — `низ X фон` и соответствующие слои, зоны — `низ X доп`, П-обрамление по X — `низ X верх X П-обрамление` (аналогично Y). П-элемент относится к обоим планам своего направления и сохраняется на разрезах. При наличии доступного параметра экземпляра `Мрк.МаркаКонструкции` в него копируется марка плиты. Фильтры конкретной конструкции в Weandrevit должны соответствовать марке этой плиты; примерный код из шаблона автоматически не заменяется. Подробности — в [исследовании шаблона](docs/weandrevit-drawing-parameters.md).

Режимы зон различаются смыслом введённых данных:

- **Ручная раскладка** — тип и шаг назначаются цветам без численной проверки требуемой As.
- **Дополнительная площадь** — назначенная интенсивность `π·d_nom²/4·1000/s` сравнивается с введённой дополнительной As.
- **Полная площадь** — из введённой As вычитается совместимый новый или полностью подтверждённый существующий фон. Проверяются грань, направление, числовой класс стали, физический диаметр, высота и пространственное покрытие потребности фактическими фоновыми рядами.

В численных режимах геометрическая полоса покрытия ограничена половиной шага по обе стороны ряда. Перед вычитанием фона проверяется выбранная область потребности внутри бетона, включая участки у концов рядов и отверстий. Это предотвращает необоснованный равномерный зачёт фона, но не рассчитывает работу стержня в зоне анкеровки или несущую способность сечения.

## Подложка и единицы

Обычный путь читает уже размещённую геометрию Revit: её масштаб, поворот, отражение и вложенные преобразования повторно не применяются. Цвет берётся из материала, при отсутствии — из слоя с диагностикой; импортировать следует с сохранением цветов.

При недоступных метаданных используется исходный **ASCII DXF с `3DFACE` в пространстве модели**. Единицы задаются явно; координаты преобразуются один раз и размещаются по трансформации импорта. Множества вершин источника и подложки сверяются **в обе стороны** с допуском 0,2 мм. Неверные единицы, неполный источник или несовпадающее размещение блокируют расчёт. Это проверка геометрического соответствия, а не происхождения чисел легенды. Binary DXF, другие типы сеток и геометрия внутри используемых блоков этим резервным путём не поддерживаются. Карта с неразрешённым цветом ByBlock исключается целиком.

Слои и отметки разделяются на самостоятельные карты; выбирается одна карта. Она должна быть плоской и параллельной плите. Допуск диапазона Z внутри группы — 1 мм без накопительного слияния соседних отметок. Непараллельные и вырожденные грани исключаются с диагностикой. Подтверждение осей пользователем необходимо: геометрический поворот скалярной карты AsY не пересчитывает потребность для другого физического направления.

## Инженерные ограничения

- Фон обрывается по защитному слою. Анкеровка в опорах, компенсация разрезанных отверстием стержней и узлы концов автоматически не проектируются.
- Длина П рассчитывается для принятых 100% растянутых стыков и полного использования площади арматуры. Проверяются полная проекция полки, место под фактический загиб и требуемый прямой нахлёст зоны. Это не расчёт несущей способности всего узла: поперечное армирование, расстояния между стыками и применимость узла к конкретной конструкции требуют проектной проверки.
- Автоматическая разбивка стержней на поставляемые длины и проектирование стыков не выполняются. Реализация замкнутых продольных контуров сохранена в Core, но не подключена к текущему MVP.
- Порядок X/Y и фактическая рабочая высота `h0` должны соответствовать исходному расчёту. MVP их с расчётной моделью не сверяет.
- Для дополнительных зон сохранена таблица анкеровки CITRUS без нормативного пересчёта. Нужен параметр класса стали с GUID `32a47c7f-e91d-4a8e-bf24-927cb679b4d1`. Прямые зоны из гладкой A240 заблокированы: требуемый способ анкеровки в этом MVP не реализован.
- Совместная раскладка допускает пересечения стержней и блокирует полные дубли; это не проверка нормативного свободного зазора или удобства бетонирования. Существующие стержни между собой, арматура других основ и связанных моделей не проверяются. Системы Path/Area без доступных физических стержней и неподдержанные кривые блокируют операцию. Для свободной формы нужен Revit 2022 или новее.
- Поддерживаются плоские плиты постоянной толщины с контурами из отрезков и дуг. У наклонной плиты верхний и нижний контуры должны совпадать при проекции вдоль нормали. Вертикальные торцы наклонной плиты, изменённая форма, переменная толщина, сплайны и эллипсы отклоняются.
- Номинальный диаметр используется для As и таблицы анкеровки, физический диаметр модели — для защитных слоёв, высот и пересечений. Максимум выбранной карты — 200 000 граней и 1 000 000 вершин; лимит общего геометрического контроля — 200 000 стержней. Превышение лимита означает незавершённую проверку и блокирует создание.

## Структура и сборка

- `SlabReinforcement.Core/` — независимое ядро netstandard2.0 / NetTopologySuite 2.6.0: раскладка, интервалы, дуги, совместный контроль.
- `SlabReinforcement/Integration/` — чтение Revit/CAD, общий снимок данных, создание и проверка стержней.
- `SlabReinforcement/Preview/`, `SlabReinforcement/CitrusTheme/` — WPF-предпросмотр и стиль проекта.
- `SlabReinforcement.Dxf/` — потоковое чтение исходного DXF и сверка вершин.
- `SlabReinforcement.Core.Tests/`, `SlabReinforcement.GeometrySmoke/`, `SlabReinforcement.UiSmoke/`, `SlabReinforcement.DxfSmoke/` — проверки без Revit.
- `SlabReinforcement.RevitSmoke/` — испытания интеграции в установленном Revit 2023 на копии модели.
- `docs/research/`, `docs/validation/` — исследования, ограничения и протоколы.

Целевые конфигурации: Revit 2019–2024 — net48; 2025–2026 — net8.0-windows; 2027 — net10.0-windows.

```powershell
dotnet build .\SlabReinforcement.sln -c R2026
```

Для R2019–R2024 используйте MSBuild из Developer PowerShell Visual Studio: `msbuild .\SlabReinforcement.sln -restore -p:Configuration=R2024`. Результат находится в `SlabReinforcement/bin/R20xx/`. Развёртывать нужно вместе с соседними Core/Dxf/NTS и прочими DLL из каталога. Сборка не копирует файлы в установленный CITRUS. Наличие целевой конфигурации не означает испытание её API на всех версиях Revit.

Для Revit 2023 предусмотрен [локальный пакет с ручной установкой](docs/deployment/revit2023-mvp.md). После финальной сборки `tools/Package-Revit2023.ps1` формирует новый каталог `artifacts/mvp-revit2023-u-only` с отдельным manifest команды, DLL, лицензиями и SHA256; установленный CITRUS и прежний пакет не меняются. Демонстрационную RVT текущего варианта можно явно включить через `-DemoModelPath`.

Проверки охватывают повороты, отверстия, вогнутые контуры, фон и обрамление, покрытие зон, анкеровочные продления, группировку, 3D-коллизии и защитные слои. UiSmoke использует рабочие XAML/логику окна с подменой типов Revit и не проверяет API. Для фактических API-прогонов используется [отдельный Revit runner](SlabReinforcement.RevitSmoke/README.md); его случаи и результаты необходимо оценивать по протоколу конкретного запуска. Финальная матрица испытаний MVP оформляется отдельно, без переноса старых чисел на изменённый код.

Для предоставленных файлов «1–4 Слой.dxf» пользователь подтвердил метры:

```powershell
dotnet run --project .\SlabReinforcement.DxfSmoke -- 'C:\Users\Misha\Desktop\Армирование плит' --units-map .\docs\validation\confirmed-dxf-units.json --benchmark
dotnet run --project .\SlabReinforcement.UiSmoke -- --source-json .\artifacts\dxf-validation\1-source.json
```

Коэффициенты в JSON относятся только к перечисленным именам файлов. Для остальных файлов без подтверждённых единиц выполняется инвентаризация исходных координат. `--benchmark` использует искусственный внешний прямоугольник и тестовую арматуру: это проверка обработки сетки, а не проект плиты. Предпросмотр исходного DXF не подставляет вымышленный контур Revit.
