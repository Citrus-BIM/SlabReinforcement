## Готовые типы погонажа

Пользователь указал, что специальный тип уже содержит нужный флажок. Полная read-only инвентаризация всех 35 RebarBarType подтвердила десять таких типов:

`ø8-пог.м.`, `ø10-пог.м.`, `ø12-пог.м.`, `ø14-пог.м.`, `ø16-пог.м.`, `ø18-пог.м.`, `ø20-пог.м.`, `ø22-пог.м.`, `ø25-пог.м.`, `ø28-пог.м.`.

У каждого `Рзм.ПогМетрыВкл=Да`, класс стали500, `Арм.КлассБетона=25`. Проверка только обычного `ø12` ранее показывала выключенный флажок; это не означало отсутствие подходящих типов в шаблоне. Для фона следует использовать существующий подходящий тип погонажа, не менять общий обычный тип стержня.

| Раздел | Штатный NUMBER_PARTITION_PARAM; доступен для записи на Area, только для чтения на её RebarInSystem |

В `КЖ_ВРС` и `КЖ_Спецификация арматуры` обнаружены вычисляемые поля `Rs`, `Rbt`, `Коэфф нахлеста`, `ПодсчетКакПогонныеМетры`, `МассаПогМетраРАСЧЕТНАЯ`. Это подтверждает наличие механизма в конкретной модели. Тексты формул API ScheduleField Revit2023 не возвращает; формулы из исторических статей не выдаются за прочитанные формулы данного файла. Итоговые значения расхода с учётом нахлёста в этом тесте не сверялись.

## Эксперимент с четырьмя системами

Revit2023 build23.0.11.19: создано четыре AreaReinforcement, ровно по одному активному слою в каждой. Максимальный шаг200мм. Тип системы из шаблона: «Армирование по площади несущей конструкции», HostStructuralRebar=true. Получено22 дочерних RebarInSystem и812 физических стержней. Данные сохранены и проверены повторным открытием.

Эксперимент использовал обычный `ø12` для геометрической проверки; это не демонстрация правильного учёта фонового погонажа. Нулевые дополнительные отступы дали одинаковые уровни X/Y: низ−159мм, верх−41мм от верха плиты. Следовательно, одного разделения на четыре объекта недостаточно для размещения направлений по высоте. Этот файл диагностический и не заменяет рабочую армированную модель.

Доказательства: `artifacts/underlay-ui-smoke/run-20261024-153614/results.json`, `native-area-poc.md`; полная инвентаризация: `artifacts/underlay-ui-smoke/run-20261024-154031/results.json`. В последнем прогоне транзакций записи0, документ и параметры не изменены.

## Применение результатов

Принятая схема: четыре native Area, готовые типы погонажа, явное разнесение X/Y по высоте, штатный «Раздел» для каждого слоя, отдельное П-обрамление. Учёт расхода на нахлёст проверяется в существующих спецификациях и не подменяется автоматической физической нарезкой фоновых стержней.

Первичные материалы автора и закреплённая версия исходного алгоритма собраны в [исследовании источников](2026-10-24-weandrevit-background-author-workflow.md). В установленную production-команду native Area ещё не интегрировано.
