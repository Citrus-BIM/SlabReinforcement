# Проверка выбранных защитных слоёв в Revit

Это план проверки API, а не отчёт об успешном запуске. Revit для этого изменения не запускался.

## Реализованная схема

Предпросмотр использует отдельные значения сверху, снизу и с торца. Значения сверху/снизу `null` в старом сценарии означают соответствующий слой текущей плиты. Снимок плиты не изменяется в рабочем потоке.

Изменение параметров плиты выполняется только после принятия окна, внутри `TransactionGroup` создания арматуры. Назначаются ссылки экземпляра плиты на подходящие `RebarCoverType`; `CoverDistance` существующего общего типа не изменяется. Если тип с требуемым значением отсутствует, он создаётся в той же транзакции.

Если в плите уже есть армирование любого обнаруженного вида (Rebar, Area, Path, RebarContainer, FabricArea, FabricSheet), изменять защитный слой этой операцией нельзя. Пользователю предлагается изменить свойства плиты и заново открыть команду. Перед записью наличие армирования и текущие параметры плиты читаются повторно. Неизменные значения слоёв сохраняют прежний процесс работы.

## Подготовка

Использовать копию тестового файла с чистой плитой из `1 Слой.dxf`. Добавить вторую контрольную плиту, которая использует те же типы защитного слоя. Снять значения и ElementId трёх параметров обеих плит, список `RebarCoverType` с расстояниями, количество и геометрию арматуры. Сначала проверить установленную сборку по SHA256 и подтвердить, что запускается команда плагина.

## Сценарии

1. Открыть команду на плите с неодинаковыми слоями, например 35/40/45 мм. Проверить три поля. Изменить их и отменить окно: параметры обеих плит, список типов и арматура не должны измениться.
2. На чистой плите задать 25/30/35 мм и создать фон. Проверить значения в параметрах выбранной плиты и неизменность контрольной. Проверить геометрию каждого физического стержня относительно выбранных слоёв. При включённом П-обрамлении учитывать существующий дополнительный резерв высоты, который этим изменением не меняется.
3. Повторить на другой чистой плите с теми же 25/30/35 мм. Подходящие типы должны переиспользоваться; количество типов не должно вырасти. Проверить случай, когда имя предполагаемого нового типа уже занято типом с другим расстоянием.
4. На плите с арматурой изменить отдельно верхний, нижний, затем торцевой слой. Каждый раз получить понятный отказ до записи. Число и полная геометрия существующих стержней, параметры плиты и список типов должны остаться прежними.
5. На той же плите оставить все три значения прежними и выполнить допустимое добавление арматуры. Ограничение изменения слоя срабатывать не должно; прежние проверки совместимости и геометрии сохраняются.
6. Через отдельную API-проверку смоделировать изменение документа после расчёта: добавить арматуру перед вызовом writer либо поменять параметр защитного слоя. Writer обязан отказать до первой транзакции. Для наличия систем проверить Area/Path даже при отсутствии сгенерированных RebarInSystem.
7. В отдельной тестовой API-команде вызвать writer с корректным предварительным планом и ошибкой создания после назначения новых cover types. Проверить откат всего TransactionGroup: старые параметры плиты, отсутствие новых стержней и отсутствие типов, созданных отменённой операцией. Не сохранять заведомо ошибочный сценарий в пользовательский файл.
8. Сохранить удачный результат, закрыть и открыть копию RVT. Повторить чтение трёх параметров, типов и геометрии. Проверить Undo одной операции: арматура и изменение защитного слоя должны отменяться вместе.

## Подтверждённая совместимость API без запуска Revit

В локальных XML пакетов 2019.0.1, 2020.0.1, 2021.1.9, 2022.1.0, 2023.0.0, 2024.2.0, 2025.0.0, 2026.0.0 и 2027.0.0 присутствуют `RebarCoverType.Create(Document, String, Double)` и `CoverDistance`. Назначение выполняется через существующие `CLEAR_COVER_TOP`, `CLEAR_COVER_BOTTOM`, `CLEAR_COVER_OTHER` с типом хранения ElementId. Методы `RebarHostData.Get*InHost` используются для проверки любого существующего армирования.

Проверки в Core покрывают legacy fallback, явные значения меньше прежних, отрицательные/нечисловые значения, отсутствие места по толщине и допуск при сравнении после преобразования единиц. Они не заменяют перечисленные проверки транзакций и фактической геометрии в Revit.
