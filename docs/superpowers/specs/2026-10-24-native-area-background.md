# Фон отдельными системами армирования по площади

## Подтверждённые требования

Пользователь подтвердил штатное «Армирование по площади» Revit и отдельно уточнил: каждый слой отдельно. Нахлёсты оформляются отдельно от создания основного фона.

| Строка интерфейса | Создаваемый объект |
|---|---|
| Низ X | AreaReinforcement, только нижнее направление X |
| Низ Y | AreaReinforcement, только нижнее направление Y |
| Верх X | AreaReinforcement, только верхнее направление X |
| Верх Y | AreaReinforcement, только верхнее направление Y |

У каждого объекта собственные тип арматуры и максимальный шаг. Отключённая строка не создаёт объект. Направление X задаёт выбранное ребро плиты. Раздельные системы должны получать согласованные отметки с учётом физических диаметров и общего П-обрамления. Порядок X/Y сверху и снизу следует отображать явно; авторский инструмент Weandrevit позволяет переставлять направления независимо, поэтому прежний фиксированный порядок нашего планировщика не принимается за рекомендацию автора.

Пользователь указал специальные типы погонажа. Проверка шаблона подтвердила 10 готовых типов `ø8-пог.м.` … `ø28-пог.м.`, включая `ø12-пог.м.`; у них уже включён `Рзм.ПогМетрыВкл`. Для фона выбираются эти готовые типы. Обычный `ø12` остаётся отдельным типом для штучного армирования. Наименование помогает выбору, но наличие режима проверяется по параметру типа, а не только по суффиксу. У всех десяти типов в проверенном шаблоне `Арм.КлассБетона=25`; его соответствие бетону плиты относится к проверке учёта погонажа.

Для четырёх систем заполняется штатный `Раздел` по верху/низу и X/Y. В испытании параметр доступен для записи на Area и только для чтения на дочернем RebarInSystem. Шаблонные типовые и экземплярные параметры не подменяются друг другом.

Обрамление — отдельные П-стержни, общие для основной арматуры и зон. Зональные добавки сохраняют свою отдельную логику. Предпросмотр должен отражать фактический нативный фон, а повторные операции — распознавать соответствующую систему слоя, включая изменённые пользователем параметры.

## Проверка перед изменением production

Уточнение по обрамлению: пользователь указал на возможное применение автором Weandrevit штатного армирования по траектории в новых материалах. Старые линейные IFC-семейства не принимаются за окончательную рекомендацию. PathReinforcement рассматривается как кандидат для общего П-обрамления; пригодность формы, защитные слои, шаг и повторное чтение должны быть отдельно проверены в Revit 2023. Подтверждённые источники и границы исследования: [обрамление Weandrevit](../../research/2026-10-24-weandrevit-perimeter-workflow.md).

Если эксперимент подтвердит пригодность Path, перед интеграцией сохраняются следующие требования:

- ExistingRebarReader читает все физические позиции RebarInSystem, включая дуги и реальные преобразования; снятия текущего запрета на системы недостаточно.
- Совпавшее П становится ReferenceBars без повторного создания. Отключение создания обрамления не отменяет геометрический резерв уже существующих П.
- PerimeterZoneEnds использует фактические станции и полные П-оси: одинаковый номинальный шаг не доказывает совпадение native Path с сеткой Core.
- Проверка записи отличает дочерние ID новых систем от существующих и сохраняет атомарный откат при несовпадении геометрии.
- Марка/Раздел системы и внутренний SpecKey не заменяют уникальную идентичность каждой физической позиции; маркировка и спецификация проверяются отдельно.

1. В отдельной копии тестовой плиты создать четыре AreaReinforcement, оставив ровно один слой в каждом.
2. Прочитать RebarInSystem всех четырёх объектов и проверить реальные направления и отметки. Определить дополнительные отступы независимых систем, если Revit не разводит их автоматически.
3. Сохранить и повторно открыть копию; подтвердить четыре независимых объекта и сохранение параметров.

## Граница текущей реализации

Сейчас BackgroundPlanner выдаёт отдельные стержни и наборы, RebarPlanWriter создаёт Rebar. ExistingRebarReader намеренно блокирует RebarInSystem. Поэтому заменить только вызов создания недостаточно: потребуются согласованные изменения предпросмотра, чтения существующей арматуры, повторных операций и взаимодействия с зонами. Эти изменения ещё не внесены; экспериментальная RVT не означает обновление установленной команды.

Проверка минимального прототипа в Revit 2023 выполнена: run-20261024-153614, четыре Area, 22 дочерних набора и 812 физических стержней, SaveAs/reopen. При нулевых дополнительных отступах X/Y каждой стороны находятся на одинаковой отметке. Это диагностический результат, а не готовая раскладка: дополнительные смещения нужны явно. Инвентаризация всех типов и параметров выполнена отдельно без записи: run-20261024-154031.
