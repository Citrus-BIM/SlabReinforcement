# Single slab from approved DXF geometry

This opt-in Revit 2023 runner creates a new project from a copied Weandrevit structural RTE and builds **only the approved footprint supplied in JSON**. It never reads `Тест.rvt` or derives a rectangular bounding-box slab. Outputs are isolated in a new `artifacts/single-slab-revit/run-*` directory; previous demonstrations remain intact.

Input contract:

- `shell`: actual boundary corners as `[x,y]` millimetres in the original DXF WCS. `holes`: an array of hole rings in the same coordinates. Removing an exact repeated closing point is allowed; the runner does not simplify or repair a contour.
- `expectedAreaMm2`, `topElevationMm`, `thicknessMm` and `sourcePlaneElevationMm`: explicit geometric/test values.
- `axisEdge.start` / `.end`: a real horizontal boundary segment in WCS millimetres. It is found on the created Revit slab; its API reference defines the reinforcement frame. The resulting local Y must be parallel to placed DXF Y.
- `cleanedDxfMmPerUnit` and `sourceUnitsToMm`: explicit unit factors. Current confirmed source/export units are metres, i.e. 1000 mm per coordinate. No unit inference or relocation is performed.

The approved input is the upper-left connected slab from `1 Слой.dxf`, KLEENKA only: 14,568 original coloured 3DFACE entities, original XYZ and colours, no PLAST duplicate. The extraction retains all real corners including the 10 mm protrusion. The 535-point raw boundary and 14-corner shell are geometrically identical, with no holes; extraction/readback is independently checked outside the runner.

The runner inventories actual template types, chooses a concrete floor type with the specified 200 mm test thickness, retains its 35 mm cover defaults, and uses the real Ø12 / steel grade 500 type. It does not invent steel class or numerical demand As. After creation and again after reopening each saved model, it compares the Revit slab with the JSON using area, symmetric difference, boundary distance, hole count, top elevation and thickness. DXF source and placed Mesh vertices must match in both directions through production `DxfMeshReader`.

Actual production Session/Writer cases use fixed manual Ø12/200 assignments: all colours; nonwhite additional bottom-X zones; four background layers; U bars on the actual boundary with 500 mm legs; and the combined zone/background/U plan. Bottom X is the user's assumption for `1 Слой`; `directionAssumption` explicitly records that this is a Manual geometry test, with no verified calculation legend or inferred As. Parallelism of the selected slab X and placed DXF X is checked separately.

This file explicitly enables `AllowBarIntersections`, as requested by the user. Intersection diagnostics remain visible warnings; containment, diameter, cover and exact-centreline checks remain blocking. Three strict cases without `UsePerimeterUForZoneEnds` still expect exactly `ANCHORAGE_DOES_NOT_FIT` and `UNCOVERED_DEMAND`. They verify Writer rejection and unchanged bar count after rollback; partial zone plans are never saved.

The nonwhite bottom-X combined case explicitly enables `UsePerimeterUForZoneEnds`: the user accepts a common U perimeter detail for the ends of straight Manual zone bars. This is geometry-only placement, not calculated anchorage credit. Assertions require actual straight zones at local Z=-135 mm, all four background layers, per-end connection evidence and the warning `ZONE_ENDS_IN_PERIMETER_U`. The inherited 500 mm U legs and strict anchorage parameters are not shortened or zeroed. Additional negative cases require the exact `ZONE_U_REQUIRES_PERIMETER` and `ZONE_U_REQUIRES_MANUAL` guards, plus Writer rejection and no persisted model changes. Numerical-As mode is not allowed to use this option.

The sequential reuse case starts again from the zero-rebar baseline. It creates the four background layers and U perimeter once, then creates nonwhite Manual bottom-X zones and top-X zones in two separate operations with `Perimeter.Enabled=false`. All perimeter type/spacing/leg/boundary settings and the four disabled background layer choices remain present for exact reference matching. The initial actual element UniqueIds, quantities and complete centrelines become the reference: every later operation and the reopened final model must retain them unchanged. New stage elements must contain only straight zones at the corresponding existing background elevation. Both directions are user-selected geometric examples on the same map, without a verified As legend.

The common geometry now uses MaximumSpacing. The runner checks the actual Revit `LayoutRule` of every multiposition background/U set after writing and reopening; it records actual baseline counts instead of asserting historical fixed-spacing counts. Zone sets keep their separate placement rule. Exact common geometry is also tested with perimeter creation still enabled: it must be reused, not duplicated. The deliberately incomplete existing perimeter must fail with `PERIMETER_PARTIAL_MATCH`; changed leg settings with creation disabled must fail with `ZONE_U_REQUIRES_PERIMETER`, and with creation enabled with `PERIMETER_EXISTING_MISMATCH`. These destructive fixtures run in outer rollback groups. Diagnostics `PERIMETER_REUSED` and `BACKGROUND_REUSED`, full reference matching and unchanged physical quantities are mandatory for successful reuse.

Two additional rollback-only Session regressions use an explicitly synthetic interior patch on the real host, without altering the DXF or saving any synthetic result. They cover a single existing Y background layer (disabled X must not shift it or cause duplicate creation), incompatible stack/type rejection, and existing U/background reference elevation when edge-ending permission is off. The source-map sequential workflow remains a separate case.

Each creation case runs inside an outer rollback group. Every input and saved-demo baseline must contain zero reinforcement. Successful demonstrations are independently regenerated, saved and reopened. A one-to-one comparison of every physical bar and every full line/arc matches endpoints and arc midpoints in 3D at 0.1 mm, without assuming collector, array or curve order. It runs after creation and again after reopening, in addition to Writer's checks, actual counts, containment and intersection policy. Maximum measured mismatch and every array position's participation are reported. A real regression on this stepped outline also checks Revit host-cover snapping to the extension of a neighbouring oblique face, for both straight background bars and the straight free ends of U bars. Explicit preferred endpoint offsets preserve the computed endpoints instead of increasing the tolerance.

Expected output names are `single-slab-input.rvt` (slab and DXF), `zones-bottom-top-x-existing-u.rvt` (three-operation reuse workflow), `zones-bottom-x-background-u.rvt` (single combined bottom-X operation), `reinforced-slab.rvt` (background/U reference without additional zones), and `background-only.rvt`. All files belong to a new unique run directory; previous models are never overwritten. Russian named overview/detail/DXF/top views are saved, with the overview as the starting view. The accepted-zone models use source zone colours, grey background and orange U bars; their detail views focus on a real zone endpoint. PNGs are exported by Revit.

The actual product DLL/BAML also receives a runtime probe: the shared-perimeter checkbox starts false, can be enabled in Manual, clears/disables when switching to AdditionalArea, and becomes available but unchecked when returning to Manual. The zones-tab perimeter creation switch must update the common switch, preserve editable reference parameters when off, and allow existing-perimeter use independently. An expanded-settings PNG records these options. The window is closed without accepting or saving settings, and settings hashes / model counts must remain unchanged. Interactive command picking/Create is not automated. Integration Session/Writer source is compiled into the harness, with exact product Core/DXF dependencies checked by SHA256.

Build production R2023 first using the workspace MSBuild configuration, then:

```powershell
dotnet build .\SlabReinforcement.SingleSlabSmoke\SlabReinforcement.SingleSlabSmoke.csproj -c Release
.\SlabReinforcement.SingleSlabSmoke\Start-SingleSlabSmoke.ps1 `
  -Footprint .\artifacts\single-slab\footprint.json `
  -Dxf .\artifacts\single-slab\1-layer-upper-left-clean.dxf `
  -Baseline .\artifacts\single-slab-revit\run-20261024-130245\single-slab-input.rvt -SkipBuild
```

The script copies inputs, checks SHA256, stages exact product dependencies into the isolated runner bin and launches its own Revit process with a unique journal-local manifest. Pre-existing Revit PIDs are recorded and never reused or closed. Only the runner's UIApplication requests ExitRevit. No production binaries, user manifests, trust settings or previous artifacts are modified.

For iterative diagnosis, `-Baseline <single-slab-input.rvt>` opens a copied baseline whose footprint is verified again; `-BackgroundOnly` limits execution to the straight-bar regression. Each invocation still uses a unique output directory. The first baseline is always created from the copied template and approved JSON.

Do not build or launch until the current production Core and R2023 are ready. The runner build precedes staging of exact product dependencies by the script.

Inspect `results.json` and each PASS/EXPECTED_BLOCKED/BLOCKED/FAILED case. `COMPLETED` alone only means execution finished. `allRequestedCasesPassed` accepts only PASS or a narrowly checked expected rejection. These are test reinforcement assignments, not a structural design or an interpretation of an absent demand legend.
